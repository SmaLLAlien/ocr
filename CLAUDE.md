# open-code-review-ts

TypeScript-порт AI-код-ревью CLI `ocr` (оригинал на Go: `D:\Projects\alibaba\open-code-review` — **эталон, не изменять**, используется только для чтения и сверки поведения).

Переносится ТОЛЬКО ядро: review диффов, scan файлов, LLM-слой, CLI и конфигурация.
НЕ переносится: bubbletea TUI, web-viewer, OpenTelemetry, npm-дистрибуция Go-бинарника, тесты (`*_test.go`).

## Протокол сессии (важно для продолжения работы в новом чате)

1. **Начало сессии:** прочитай `PROGRESS.md` — секции «Текущее состояние» и «Следующий шаг». Затем открой нужную секцию `docs/PLAN.md` (полный план миграции: карта Go-пакетов, стек, фазы, контракты).
2. **Во время работы:** сверяйся с Go-исходниками эталона (пути к файлам указаны в PLAN.md, Часть 1).
3. **Конец каждого рабочего блока:** обнови `PROGRESS.md` (отметь сделанное, впиши «Текущее состояние» и «Следующий шаг», допиши «Журнал решений» при новых решениях) и сделай git-коммит. Коммиты — часто, минимум один на завершённый пункт чек-листа.
4. Никогда не полагайся на память чата — всё важное фиксируй в PROGRESS.md.

## Ключевые документы

- `docs/PLAN.md` — полный план миграции (карта каждого Go-файла, целевая структура, фазы, контракты, риски). Источник истины по архитектуре.
- `PROGRESS.md` — чек-листы вех M1–M7, текущее состояние, журнал решений. Источник истины по прогрессу.

## Жёсткие правила

1. **Ассеты байт-в-байт.** Промпты, `tools.json`, `system_rules.json`, `rule_docs/*.md`, шаблоны копируются из Go-репо без изменений и никогда не редактируются.
2. **Три файла портируются построчно** (рядом с открытым Go-оригиналом, без «творчества»): `internal/diff/resolver.go` → `src/diff/resolver.ts`, `internal/llmloop/compression.go` → `src/loop/compression.ts`, `internal/llm/resolver.go` → `src/llm/resolver.ts`. Остальное — идиоматичный TS по описанию из PLAN.md.
3. **Контракты не ломать** (PLAN.md, Часть 4): имена команд/флагов CLI, JSON-схема `--format json`, env-переменные и порядок их приоритетов, формат `~/.opencodereview/config.json` и `rule.json`, формат сессий JSONL, плейсхолдеры `{{...}}` в промптах.
4. Тесты не пишем и не переносим — паритет проверяем ручным прогоном против Go-бинарника (команды сверки указаны в PROGRESS.md у каждой вехи).

## Стек

Node ≥ 20, ESM, TypeScript strict, commander, @anthropic-ai/sdk, openai, js-tiktoken, picomatch, @modelcontextprotocol/sdk, p-limit, execa, zod, @clack/prompts, picocolors, diff, tsup.

## Сборка и запуск

```
npm run build        # tsup → dist/
node dist/cli.js …   # или npm link → ocr …
```

Эталонный Go-бинарник для сверки: собрать в эталонном репо `make build` (или `go build ./cmd/opencodereview`).
